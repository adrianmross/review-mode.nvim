OVERVIEW                                                  *review-mode-overview*

review-mode.nvim keeps GitHub pull request review in ordinary file buffers. It compares the
current branch to the PR base, sets Gitsigns to that base when available, loads
review comments asynchronously, and provides commands for jumping through PR
hunks, PR comments, and changed files.

The plugin uses `gh` for PR metadata, comments, replies, thread state, checks,
and browser handoff metadata. The default comment sign is a Nerd Font glyph;
set `comments.sign_text` to a plain character if your font does not have it.
Picker integrations for snacks.nvim and Telescope are optional and fall back
to vim.ui.select.

==============================================================================
THE MODE                                                      *review-mode-mode*

The mode and the review session are separate. The session holds the PR context
(base ref, changed files, comments, viewed state); the mode is the key layer
and decorations over it.

Stepping out with |:ReviewModeLeave| restores your own mappings and puts the
Gitsigns gutter back to the index, so you can stage and commit normally, while
comment signs and nvim-tree markers stay visible and nothing is re-fetched.
Stepping back in with |:ReviewModeEnter| is instant. |:ReviewModeStop| is what
ends the session.

Keys installed while in the mode (see mode.keys to change them):

        ]h / [h         next / previous PR hunk
        ]c / [c         next / previous PR comment
        ]f / [f         next / previous changed file
        gt              toggle the thread panel |review-mode-panel|
        <Tab>           mark viewed, jump to next unviewed file
        <S-Tab>         toggle viewed
        <Esc>           step out of the mode

A mapping shadowed by the layer is saved on entry and restored on exit.

A commit made during the review joins it: the reflog is watched, and on the
next FocusGained, BufEnter or TermLeave the changed files and hunks are rebuilt
and the PR head SHA is re-fetched so new comments anchor to a commit GitHub
knows. Viewed state and loaded comments are kept. Set follow_head = false to
require |:ReviewModeRefresh| instead.

With mode.workspace = "tab" the review keeps its own tabpage: entering focuses
it, leaving returns to the previous tabpage, and the layout survives in
between. Ending the session closes it. The default "inplace" leaves your
windows alone.

                                                        *review-mode-statusline*
vim.g.review_mode is "mode", "session", or nil.
require("review_mode").statusline() returns a short summary such as
"REVIEW owner/repo#123 3/12".

Review is a key layer over normal mode, not a real Vim mode, so mode() never
returns it and a statusline's stock mode component cannot show it.
require("review_mode").mode_text() stands in for that component: "REVIEW" while
the layer is live and you are in normal mode, "REVIEW INSERT" once you step
into another mode, and the plain mode name with no review, so normal/insert
context stays visible. It takes { label = "PR", separator = "." }.

With lualine: sections = { lualine_a = { { require("review_mode").mode_text } } }

The plugin fires these |User| autocommands: ReviewModeStart, ReviewModeEnter,
ReviewModeLeave, ReviewModeStop.

THREAD PANEL                                                 *review-mode-panel*

|:ReviewModePanel| opens a vertical split beside the file. It follows the
cursor: threads anchored to the current line, or every thread in the file when
the cursor is not on one. A thread shows its author, their association with the
repository, how long ago it was written, the reply chain, emoji reactions, and
whether it is open, resolved, or outdated. Fenced code inside a comment is
drawn as code instead of as more prose, and a `suggestion` block is drawn as
the diff it would apply: the lines it replaces above the lines it proposes.

Keys inside the panel:

        r       reply to the thread under the cursor
        c       comment on the line the code window is on
        R       resolve or unresolve the thread
        a       apply the thread's suggestion to the buffer
        o       open the comment on GitHub
        <CR>    jump to the thread's line in the code window
        ]c [c   next / previous thread in the panel
        gr      reload comments from GitHub
        +       react to the comment under the cursor
        e       edit your comment under the cursor in a draft buffer
        D       delete your comment under the cursor, after a confirmation
        q       close the panel

Resolved threads are hidden in the panel and in |:ReviewModeThread| unless a
line has nothing else on it. Set comments.show_resolved = true to always show
them.

                                                       *review-mode-reactions*
The panel's `+` key and |:ReviewModeReact| toggle one of GitHub's eight
reactions on a comment. Your own reactions are highlighted with
ReviewModeReactionOwn and marked in the picker, and choosing one you already
added removes it. Nothing is confirmed first: a reaction is cheap to undo.
Comments loaded through the REST fallback can only gain a reaction; removing
one needs a GraphQL id they do not carry, so removal is refused.

                                                           *review-mode-draft*
|:ReviewModeReply|, |:ReviewModeCompose| and the panel's `r` and `c` keys open a
markdown draft buffer rather than a vim.ui.input prompt, so a reply can be more
than one line and can be edited before it goes out. Nothing reaches GitHub
until the draft is confirmed.

        <C-s>   post, after a prompt showing what will be sent
        :w      same as <C-s>
        <C-r>   quote the lines selected in the code window, with their path
                and line numbers
        <C-g>   seed a ```suggestion block from the lines the draft targets
        q       discard the draft

<C-r> is what lets a reply point at lines other than the one the thread is
anchored to: select them in the code window, return to the draft, press it.

COMMANDS                                                  *review-mode-commands*

                                                        *:ReviewMode*
:ReviewMode
        Toggle Review Mode. Starts the review session if there is none,
        otherwise steps into or out of the mode. See |review-mode-mode|.

                                                        *:ReviewModeEnter*
:ReviewModeEnter
        Step into Review Mode without reloading the session.

                                                        *:ReviewModeLeave*
:ReviewModeLeave
        Step out of Review Mode, keeping the session loaded.

                                                        *:ReviewModeActions*
:ReviewModeActions
        Open an action picker for common PR actions, using the configured picker
        provider.

                                                        *:ReviewModeBrowser*
:ReviewModeBrowser
        Open the current PR in your browser.

                                                        *:ReviewModeCopyUrl*
:ReviewModeCopyUrl
        Copy the current PR URL to registers.

                                                        *:ReviewModeChecks*
:ReviewModeChecks
        Show `gh pr checks` output in a floating preview.

                                                        *:ReviewModeStatus*
:ReviewModeStatus
        Show current PR status in a floating preview.

                                                        *:ReviewModeStop*
:ReviewModeStop
        Stop Review Mode and clear plugin state.

                                                        *:ReviewModeRefresh*
:ReviewModeRefresh
        Reload changed files and review comments.

                                                        *:ReviewModeNextHunk*
:ReviewModeNextHunk
        Jump to the next PR hunk, wrapping across files.

                                                        *:ReviewModePrevHunk*
:ReviewModePrevHunk
        Jump to the previous PR hunk, wrapping across files.

                                                        *:ReviewModeNextComment*
:ReviewModeNextComment
        Jump to the next PR comment.

                                                        *:ReviewModePrevComment*
:ReviewModePrevComment
        Jump to the previous PR comment.

                                                        *:ReviewModeNextFile*
:ReviewModeNextFile
        Jump to the next changed file.

                                                        *:ReviewModePrevFile*
:ReviewModePrevFile
        Jump to the previous changed file.

                                                        *:ReviewModeOldToggle*
:ReviewModeOldToggle
        Toggle the base version or unified diff for the current file.

                                                *:ReviewModeDiffLayoutToggle*
:ReviewModeDiffLayoutToggle
        Toggle the open diff between side-by-side and unified layout.

                                                  *:ReviewModeDiffFullToggle*
:ReviewModeDiffFullToggle
        Toggle the open diff between condensed context and full-file context.

                                                        *:ReviewModeThread*
:ReviewModeThread
        Show PR comments on the current line.

                                                        *:ReviewModeReply*
:ReviewModeReply
        Reply to the latest PR comment on the current line.

                                                        *:ReviewModeResolveThread*
:ReviewModeResolveThread
        Resolve the PR review thread on the current line.

                                                        *:ReviewModeUnresolveThread*
:ReviewModeUnresolveThread
        Unresolve the PR review thread on the current line.

                                                        *:ReviewModeReact*
:ReviewModeReact [content]
        Toggle a reaction on the latest PR comment on the current line, or on
        the comment under the panel cursor. Without an argument, pick one of
        THUMBS_UP, THUMBS_DOWN, LAUGH, HOORAY, CONFUSED, HEART, ROCKET, EYES.
                                                        *:ReviewModeEditComment*
:ReviewModeEditComment
        Edit your most recent PR comment on the current line in a draft
        buffer, confirmed before it is sent. Only comments you wrote can be
        edited; comments loaded through the REST fallback are refused.

                                                        *:ReviewModeDeleteComment*
:ReviewModeDeleteComment
        Delete your most recent PR comment on the current line, after a
        confirmation showing its first line.

                                                        *:ReviewModePanel*
:ReviewModePanel
        Toggle the thread panel beside the current file.

                                                        *:ReviewModeCompose*
:ReviewModeCompose
        Draft a PR comment for the current line or visual range in a buffer,
        confirmed before it is sent.

                                                        *:ReviewModeApplySuggestion*
:ReviewModeApplySuggestion
        Apply the suggestion on the current line to the buffer, leaving it
        unsaved.

                                                        *:ReviewModeComment*
:ReviewModeComment
        Create a PR comment on the current line or visual range.

                                                        *:ReviewModeSuggest*
:ReviewModeSuggest
        Create a GitHub suggestion comment on the current line or visual range.

                                                        *:ReviewModeViewedToggle*
:ReviewModeViewedToggle
        Toggle viewed state for the current PR file.

                                                        *:ReviewModeViewedNext*
:ReviewModeViewedNext
        Mark the current PR file viewed and jump to the next unviewed file.

                                                        *:ReviewModeViewedFeatureToggle*
:ReviewModeViewedFeatureToggle
        Toggle viewed-state tracking on or off.

                                                        *:ReviewModeCommentsToggle*
:ReviewModeCommentsToggle
        Toggle PR comments on or off.

                                                        *:ReviewModeViewedList*
:ReviewModeViewedList [all|viewed|unviewed]
        Open a PR file list by viewed state, with additions/deletions. The
        snacks.nvim and Telescope providers add a diff preview and toggle
        viewed state for the selected file with <Tab> or <C-t>.

                                                        *:ReviewModeViewedClear*
:ReviewModeViewedClear
        Clear local viewed state for the current PR.

                                                        *:ReviewModeViewedSync*
:ReviewModeViewedSync
        Pull viewed state from GitHub for the current PR.

                                                        *:ReviewModeViewedSyncToggle*
:ReviewModeViewedSyncToggle
        Toggle GitHub viewed-state sync.

                                                        *:ReviewModeSummary*
:ReviewModeSummary
        Show file, comment, thread, and viewed-sync counts.

                                                        *:ReviewModeCheckout*
:ReviewModeCheckout {number|url}
        Review a PR without checking it out. Fetches the PR head into
        refs/review-mode/pr/{number} (pull/{number}/head, so fork PRs work),
        puts a detached worktree for it under
        stdpath("cache")/review-mode/worktrees/{owner}_{repo}/pr-{number}, and
        opens the review in its own tabpage with a tab-local cwd. The current
        checkout, branch and working tree are untouched. Set the
        hooks.prepare_checkout override to create the worktree with your own
        tool and return its path instead.

                                                        *:ReviewModeCheckoutClean*
:ReviewModeCheckoutClean [pr]
        Remove review worktrees created by |:ReviewModeCheckout|, after a
        confirmation. Worktrees with uncommitted changes, and the one the
        current session is using, are refused and listed. A dirty worktree is
        also never updated: reviewing its PR again reuses it as it stands and
        warns.

                                                        *:ReviewModeQuickfix*
:ReviewModeQuickfix [unresolved|all]
        Fill the quickfix list with the PR review threads and open it. The
        default follows comments.show_resolved; "all" also lists resolved
        threads, marked [resolved].

                                                        *:ReviewModeDiagnosticsToggle*
:ReviewModeDiagnosticsToggle
        Toggle review threads as vim.diagnostic entries.

<

==============================================================================
PICKER PROVIDERS                                          *review-mode-pickers*

ReviewMode can use vim.ui.select, snacks.nvim, or Telescope for
:ReviewModeActions and :ReviewModeViewedList. The default picker.provider =
"auto" tries snacks.nvim first, then Telescope, then vim.ui.select. Set
picker.provider to "native", "snacks", or "telescope" to prefer one provider.

The "native" provider is plain vim.ui.select: same file labels, but no diff
preview, no live filtering and no in-picker viewed toggle. External providers
are optional. If a requested provider is unavailable or fails, ReviewMode falls
back to vim.ui.select.

SETUP                                                        *review-mode-setup*

>
  require("review_mode").setup({
    auto_open_first_change = true,
    follow_head = true,
    comments = {
      enabled = true,
      cache_ttl_seconds = 300,
      sign_text = "", -- Nerd Font glyph
      sign_hl_group = "DiagnosticInfo",
      virtual_text = true,
      show_resolved = false,
      diagnostics = {
        enabled = false,
        severity = { unresolved = "INFO", outdated = "HINT", resolved = "HINT" },
        display = { signs = false, virtual_text = false, underline = false },
      },
    },
    panel = {
      auto_open = false,
      follow_cursor = true,
      position = "right",
      width = 60,
    },
    diff = {
      fast_diffopt = "internal,filler,closeoff,indent-heuristic,linematch:0",
      full_file = false,
      layout = "side_by_side",
      partial_line_highlights = true,
      unified_context = 3,
      use_fast_diffopt = true,
    },
    gitsigns = {
      enabled = true,
    },
    nvim_tree = {
      enabled = true,
      show_comments = true,
      show_viewed = true,
    },
    mode = {
      enabled = true,
      workspace = "inplace",
      signs_when_out = true,
      gitsigns_follows = true,
      keys = { ... },
    },
    picker = {
      provider = "auto",
    },
    checkout = {
      cleanup = "manual",
    },
    viewed = {
      enabled = true,
      sync = false,
      state_path = nil,
    },
    performance = {
      ui_refresh_debounce_ms = 50,
      hunk_prefetch = {
        enabled = true,
        count = 8,
        concurrency = 2,
        focused_delay_ms = 0,
        gitsigns_delay_ms = 5,
      },
      background_hunk_scan = {
        enabled = true,
        max_files = 5000,
        delay_ms = 250,
      },
    },
    commands = true,
  })
<

ReviewMode loads PR metadata and changed-file status asynchronously. If
GH_REVIEW_BASE is set by a launcher, changed-file loading starts immediately
without waiting for GitHub metadata. Hunk locations are loaded lazily per file,
with immediate focused-file prefetch, opportunistic gitsigns.nvim hunk-cache
reuse, and an optional delayed background scan for PRs under
performance.background_hunk_scan.max_files.

The nvim-tree integration marks unviewed changed files and closed parent
folders with `☐ N`, where `N` is the number of unviewed changed files under
that node. Viewed files and closed folders use `✓`, and files and closed
folders with unresolved comments also use ` N`. An open folder hides these
folder markers because its children show the same state inline. A folder
switches to viewed after every changed file under it is viewed.

External launchers can provide GH_REVIEW_REPO, GH_REVIEW_PR, GH_REVIEW_BASE,
and GH_REVIEW_HEAD to avoid startup discovery calls.

:ReviewModeCheckout reviews a PR in a detached worktree of its own instead,
leaving the current checkout alone; review worktrees are only ever removed by
:ReviewModeCheckoutClean, which is what checkout.cleanup = "manual" means. The
hooks.prepare_checkout override decides where that worktree comes from, and
the checkout_ready and checkout_removed events report when one is ready or
gone.

Viewed state is persisted in stdpath("state")/review-mode-state.json by default.
Set viewed.sync = true or run :ReviewModeViewedSyncToggle to pull GitHub's PR file
viewed state at startup and push local viewed/unviewed toggles back to GitHub.

ReviewModeOldToggle uses the built-in Neovim side-by-side diff backend by
default. Set diff.layout = "unified" or run :ReviewModeDiffLayoutToggle to use an
inline unified diff buffer in the current window instead. Closing unified mode
restores the original file buffer. Set diff.full_file = true or run
:ReviewModeDiffFullToggle to show full-file context. Condensed unified diffs use
diff.unified_context common lines around each hunk, and condensed side-by-side
diffs fold unchanged regions in both diff windows. When diff.use_fast_diffopt is
enabled, side-by-side diffs temporarily apply diff.fast_diffopt and restore the
previous diffopt when the split closes. Unified diffs highlight changed spans
inside modified lines with DiffText; set diff.partial_line_highlights = false
to disable those inline spans.

                                                    *review-mode-diagnostics*
Set comments.diagnostics.enabled = true (or run :ReviewModeDiagnosticsToggle)
to publish every visible thread as a vim.diagnostic entry in the
review_mode_diagnostics namespace, so ]d, vim.diagnostic.open_float, Trouble
and statusline diagnostic counts work on review comments. The message is the
latest comment's author and first line, with a reply count, and user_data
carries the thread id and comment URL. Unresolved threads default to INFO,
resolved and outdated ones to HINT; comments.show_resolved decides whether
resolved threads appear at all.

It is off by default because it mixes review comments into every diagnostic
consumer. The namespace itself draws nothing (comments.diagnostics.display sets
signs, virtual_text and underline to false), because the plugin already draws
comment signs and end-of-line virtual text and the two displays would double up.

:ReviewModeQuickfix fills the quickfix list with the same threads across every
changed file, and review_mode.api.quickfix_items() returns those items without
setting the list.
